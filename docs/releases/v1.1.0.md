## Deep Defense 1.1.0

A review of the construction came back with six findings. Three could be fixed
outright and are. The other three cannot be closed by any program — only made
detectable, undoable, or checkable by someone else — and this release does exactly
that. The work turned up two older defects on the way, both in the rollback
protection, and both are fixed.

### A FILE FROM BEFORE A PASSWORD CHANGE NO LONGER PASSES FOR CURRENT

After the master password was changed, the record kept for the *old* key stayed at
the last revision written under it, and nothing ever updated it again. So the file
from just before the change opened under the old password as **verified** — the
exact swap the rollback warning has always described: put back the old file, and
wait for the old password to be tried.

Changing the password, or the work factor, now retires the old key's record with a
marker no revision can reach. A file that key still opens is named for what it is:
a copy from before the key change. The marker is the same size as every other
record, so the store does not show how many times a password was changed.

### THE ROLLBACK RECORD HAS A SECOND WITNESS

Delete the record, or put it back from the same snapshot as the file, and an older
copy used to look like a first visit or pass outright. Every open now also compares
the file with the backups beside it and with the mirror — with the key already
derived, no second Argon2 pass — and names a newer copy when one exists. It can be
put back from the same prompt, with or without a container, and the file it
replaces becomes backup 1. Nothing is written when an open is refused.

When there really is nothing left to compare with, the program says so on the way
in. Only you know whether it is really your first time on that computer.

### A DECOY AND A HIDDEN VAULT NO LONGER ERASE EACH OTHER'S RECORD

There was one record per computer, and each open replaced it: for anyone with a
hidden vault, rollback protection covered neither. Records are per slot now, with a
placeholder for every slot of the file, so the store looks the same whether or not a
second vault exists. A record that disappears on a computer the vault has been on is
reported as removed, not taken for a first visit.

### A SECOND HIDDEN VAULT CAN BE UNDONE

Creating one under a different password still destroys the first. Nothing can warn
by checking, because finding a hidden vault without its password is what the format
prevents. But the save that does it keeps the previous file as backup 1, and backups
can now be restored from the lock screen — where the loss is noticed — and from
Settings. The program says so before the button and after it.

### A FILE CAN NO LONGER ASK FOR MORE THAN THE MACHINE HAS

Argon2 parameters are read from the header before anything in the file is
authenticated. They were bounded below only; `m_cost` is a `u32`, so a crafted file
could ask for four terabytes, and a failed allocation ends a Rust process. They are
bounded above now — 2 GiB, 16 passes, 16 lanes, the largest the program's own
settings can make — and refused before a byte is allocated. Saves are also flushed
through the directory entry, not just the file, before the rename that commits them.

### THE FORMAT IS WRITTEN DOWN, AND A SECOND IMPLEMENTATION AGREES

[`docs/FORMAT.md`](https://github.com/N0deZ3r0/deep-defense/blob/v1.1.0/docs/FORMAT.md)
specifies every byte the program writes. `tools/reference_vault.py` implements the
vault format from that text on different libraries — OpenSSL, and the Argon2
authors' own C code — after checking itself against the published RFC 5869 and
XChaCha20 vectors. The Rust has to produce the same bytes, and to open a vault file
the Python wrote. [`docs/REVIEW.md`](https://github.com/N0deZ3r0/deep-defense/blob/v1.1.0/docs/REVIEW.md)
sets out the threat model and the questions for whoever reviews it next.

### THE SCREENS ARE DRAWN IN CI

New screens used to go unseen on the machine this is written on, where Smart App
Control refuses freshly built executables. egui's own test harness now draws the
real screens on WARP, the software Direct3D adapter every Windows runner has, and
each of those tests asserts on the accessibility tree as well.

The first things they found were not visual. The rows of the entry list are
painted by hand, and a screen reader met each of them as a button called nothing;
every row is now announced by its name, its badges as the words they show, and its
username. The status chips — the countdowns to the lock and to auto-type, whether
the rollback record checked out — were painted and never said; they are read out
now too.

378 tests — 369, and nine that draw the screens — up from 281 in 1.0.0. The release is built by GitHub Actions from
the tagged commit, after the tests pass.

## Install

Download `deep-defense.exe` and run it. That is the whole procedure — no installer,
no administrator rights, no runtime to fetch.

**Check the fingerprint before running it:**

```powershell
(Get-FileHash -Algorithm SHA256 .\deep-defense.exe).Hash
```

```
{{SHA256}}
```

A swapped executable is the end of everything this program protects — it would
simply read the password as you type it. There is no signing certificate here, so a
fingerprint recorded at build time is the next best thing. It is not a defence
against someone who replaces both the file and the fingerprint; it turns "is this
the file that was built?" into a question with an answer.

Built from `{{COMMIT}}` by the release workflow, Rust 1.98, target
`x86_64-pc-windows-gnu`. Rust builds are not reproducible byte for byte, so a build
of your own from this tag will hash differently — build it yourself and trust that
instead, if you prefer.

Vaults made by 1.0.0 open unchanged. The first open under 1.1.0 moves the rollback
record to its per-slot form.

## Known limits

Seventeen of them are listed in the README, with the reason for each. The first is
still the one worth repeating: **this has not been audited.** One author, no
external review. What can be done short of that has been done, and `docs/REVIEW.md`
is there to make the rest cheap.

Found a security problem? [Report it privately](https://github.com/N0deZ3r0/deep-defense/security/advisories/new)
rather than in a public issue.
